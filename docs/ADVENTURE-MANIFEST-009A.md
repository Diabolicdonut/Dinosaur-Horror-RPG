# Checkpoint 009-A — Versioned Adventure Definition and Runtime Save Boundary

**Date:** 2026-10-25. **Recovered baseline:** main `e9d0cdc983aee53eee1744ef9a1ea2bd551c1ffd`, checkpoint 007-M1 v0.7.20, **454/454** accepted tests, GitHub Actions/Pages green, open PRs none. This is the first **executable** slice of [Adventure/Engine Separation](ADVENTURE-ENGINE-SEPARATION.md) and [Procedural Replayability](PROCEDURAL-ADVENTURES-REPLAYABILITY.md).

## What is implemented

- `src/adventure-definition.mjs` defines versioned, **JSON-only** adventure declarations, a typed objective/effect grammar (`flag` and `end`), validator, reproducible noncryptographic content fingerprint, seeded variant compiler, compiled-manifest integrity check and stable save identity binding. Routes must refer to real locations, currently require **bidirectional connected** exits, objective prerequisites must be valid and acyclic, initial stock and items must be declared, creatures must be physically placed, and clue variants must identify actual rooms. Unsupported arbitrary code effects reject.
- `adventures/after-the-storm.mjs` is a **transitional adapter** that projects the accepted `SCENARIO` room map, items, original rescue objective and Velociraptor into a validated content manifest. The original accepted scenario source and its individual mechanical rules are **not yet extracted from the Party engine**.
- `adventures/ridge-survey.mjs` is a substantially different **data fixture**, *The Long Count*: five research-field locations, a field survey objective, collecting observations and walking out instead of a radio/beacon/helicopter rescue, a calm Parasaurolophus, plus authored alternative research obstacles and wildlife dispositions. It **compiles and validates but is not yet playable** through the legacy Party engine.
- `src/adventure-catalog.mjs` allows selecting/copying the two manifests and compiling seeded instances without mutable global content. Separate seeded world-content RNG is independent from Evolved gameplay RNG. The initial variant compiler can select different committed latent causes/dispositions by seed; this does **not** yet project all those options onto the existing game runtime.
- New `newPartyIncident` saves contain a **versioned adventure binding** (adventure ID, revision, schema version, content fingerprint) for After the Storm. `isPartySave` rejects mismatched bindings. Existing accepted Party-v3 and migrated v2 saves **without the optional binding remain legal**, with no changes to combat/stress/action/creature rules. The new source import version is reflected in the browser and previous browser-contract tests.

## Scope boundary and design caution

**Not yet accomplished:** a truly scenario-agnostic Party engine, gameplay with two different selectable adventures, immutable cryptographic content signing, live generation of entire adventure maps/creatures/quest outcomes, procedural campaigns, an autonomous AI Game Mother or manually tested graphical play. Specifically, the main engine and directors still import or assume the hardcoded Nublar `SCENARIO`. `ridge-survey` is currently a *compiler/validator fixture only*. The structural validator's declared effects are not yet enacted by a generic action interpreter; ordinary Evolved checks still run through the accepted Party engine.

The fingerprint uses FNV-1a for reproducibility and version drift detection, **not as a security signature**. The compiled manifest is copied and validated against deterministic recompilation; it must ultimately be stored or locked by version for long-running Campaign saves, rather than silently regenerated after generator changes. This step does not retrofit random hidden truths into After the Storm's original play. A seeded generator does not promise adjacent seeds always differ, only that broad seed ranges produce genuine variant possibilities while identical inputs reproduce exactly.

The current initial manifests intentionally restrict physical exits to symmetric connected graphs; one-way routes require later typed traversal rules. Do not drop prior playability merely to satisfy the new schema. Expand schema features and typed consequences only with cross-adventure tests.
