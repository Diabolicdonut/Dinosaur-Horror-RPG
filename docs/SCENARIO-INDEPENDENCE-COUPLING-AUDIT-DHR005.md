## Required migration interfaces (design, **not** implemented here)

1. **AdventureRegistry**: `resolve(id, revision, fingerprint)` returns immutable, version-pinned definition/compiled instance or an explicit missing-source failure; never silently use current revision. Register transitional Nublar adapter separately. Content provenance includes generator version and exact approved manifest. Raw client `scenario` is not proof of authority.
2. **ScenarioContext**: `{identity, definition, world, capabilities, speciesProfiles, ruleProfile, historicalCompatibility}` is immutable per save. Services accept context, not imports of `SCENARIO`. Historical feature profile is keyed by **(adventureId,revision)** and cannot be inferred from a different adventure's revision number.
3. **WorldTopology + Perception**: legal connected moves, typed edges/occluders/doors, light/sound/weather, finite item/actor locations, reachable action targets. `projectObservation` returns actor-scoped knowledge and view-only data; `GMPrivateView` stays separately access-controlled. Tactical Map only consumes a filtered display projection; never resolves truth from pixels.
4. **TypedAction/EffectRegistry**: schemas for move, investigate, use system, interact, perceive, medical, attack, withdraw, NPC act, scene and objective with `preconditions -> authorized Evolved check -> atomic effects -> events`; source-defined targets, skills and finite resources. Rejected intents leave state, RNG, clock and event journal unmodified. Narrative text/AI cannot commit effects.
5. **Actor/Creature/NPC entity contracts**: stable IDs and positions, owner/controller, observation and knowledge provenance, source-bounded species/talent/gear profiles, action budgets, resource conservation, credible encounter responses. Species profiles are source-reviewed; no invented published mechanics.
6. **DurableSaveEnvelope**: explicit format ID and version, locked compiled manifest identity, RNG/seed, clock/turn, action+evidence journal, per-actor knowledge, entity ledger, Campaign chapter ledger. Loading uses a **pure migration then strict validation**; historical Nublar 006.2 and Party v2/v3 remain importable. Keep old storage keys separate until an explicitly tested archive migration.
7. **AdventureOutcome & presentation DTO**: neutral internal `completed/abandoned/lost` plus legacy `rescued` mapping for old saves; consistent inventories, creature display, actor summary, objectives and per-mode privacy. Client has no trusted authority over secret state.

The **current** manifest validator only supports certain fields and effects; expanding these interfaces is a series of versioned, independently reviewed implementations, not a license for arbitrary schema additions or Evolved rules changes.
