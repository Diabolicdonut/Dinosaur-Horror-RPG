# DHR-027 — Evolved Panic: source-grounded Freeze consequence

**Assigned:** [Issue #92](https://github.com/Diabolicdonut/Dinosaur-Horror-RPG/issues/92)  
**Scope:** one opt-in, reusable, deterministic consequence adapter; no live runtime wiring and no roadmap acceptance change.

## Authority and bounded choice

The **private user-supplied *ALIEN RPG — Evolved Edition*** is primary (see `docs/EVOLVED-RULES-AUTHORITY.md`). The standard **Stress & Panic** procedure at printed **pp. 72–73** makes a panic roll of D6 + existing stress − Resolve, with **result 7, Freeze**, denying interrupts until the character forfeits their next turn. A witnessed fellow player character becoming Broken is an explicit panic trigger on p. 72.

`src/evolved-checks.mjs` already provides the accepted seeded roll and returns the `freeze` classification, but a stand-alone die classification does not authorize actual action/turn effects. The new `src/evolved-panic-freeze.mjs` **reuses that resolver exactly**, consuming no new random draw and leaving stress and die distributions untouched.

This implementation deliberately only covers a **verified combat witness to another PC becoming Broken**, and only the **Freeze (7)** consequence. It cannot be invoked for an unspecified atmosphere beat, arbitrary GM declaration or a different response. It does not grant the AI permission to declare a character Broken or choose a die result.

## Data contract

The adapter takes a validated Evolved character sheet and a **trusted engine-produced** encounter snapshot with:

- `phase: 'combat'`, current `turn: {sequence, actorId}` with monotonically increasing slot sequence;
- unique `actors` with actual `id`, `zone`, `health`, `broken` and `dead` states;
- the latest committed `pc_broken` event containing the victim ID, transition from positive Health to zero, event zone, current sequence and **prevalidated observer IDs** (`witnessedBy`).

The actor must be alive, not Broken, and in the victim's actual zone. The victim must be another living, newly Broken PC. The event must have been witnessed, not simply guessed from scene narration. The invoking engine—not a language model or client request—must own the world event, visibility evidence, seed and saved consequence ledger. **This pure module cannot cryptographically authenticate caller-supplied state**; rejecting forged JSON within an untrusted boundary requires the consuming engine's trusted-state gate.

`applyFreezeConsequence` rerolls the exact authoritative `resolvePanic(character,{seed})` result, accepting only `kind === 'freeze'` and `value === 7`. It returns a cloned character with the response recorded and a separate versioned ledger. No existing save schema is modified, and no new ledger is silently inserted into old saves.

`authorizeFreezeAction` is the mandatory check before scheduler-controlled **interrupt, quick or full actions**: interrupts are rejected while Freeze is pending; the next actor turn cannot be used for ordinary actions until forfeited. A same-slot ordinary action is not newly prohibited by this adapter: the source specifically defines a *next-turn* loss, and existing action economy remains authoritative.

`consumeFreezeTurn` forfeits exactly one next actor turn, requiring the engine's consecutive slot history **from the triggering slot forward** with no earlier actor turn. The module clears that one Freeze response and records the consumed slot. Duplicate/later/replayed consumption is rejected. No timer, move, NPC action, combat damage, or other game state is generated by the adapter.

## Integrity and test boundaries

`validateFreezeLedger` checks the event ledger version, unique event IDs, one pending Freeze per actor, original die/seed/stress/Resolve correspondence and consumed-turn chronology. The adapter returns refusal without modifying its inputs for unverified events, missing witness evidence, dead/Broken participants, non-Freeze dice, repeated events and overlapping Freeze. An already-active same-named response would call for the Evolved repeated-response escalation procedure; **that procedure is not implemented here**, so this slice explicitly refuses it rather than silently stacking or inventing a replacement result.

Regression file: `tests/evolved-panic-freeze-dhr027.test.mjs`. Coverage includes genuine consequence, seed replay, false physical/world evidence, forged result, duplicate trigger, overlapping state, action gating, full-turn forfeit, corrupt journals, old-sheet nonmutation and identical decisions in Party/Focus/Spectator. Existing `src/evolved-checks.mjs`, both gameplay engines, `src/combat-turns.mjs`, Worker, UI, adventure manifests, historical save fixtures and accepted progress ledgers are untouched.

## Required integration before calling this playable parity

1. The Integration Director should review the source mapping with the private PDF and verify the PR-head `npm test` and syntax CI; do not merge automatically or award roadmap credit.
2. A future owner of the combat scheduler must emit genuinely witnessed `pc_broken` events and monotonic per-slot histories, call `applyFreezeConsequence` once from the trusted panic trigger, persist the opt-in ledger, and invoke `authorizeFreezeAction` before every relevant turn/interrupt. `consumeFreezeTurn` must run at the first subsequent actor turn without advancing it as a player action.
3. The authoritative state validator must reconcile ledger entries with the original committed event, seed and current actor sheet, including load/replay; old saves without this optional extension must remain on their original logic path. Independently test restored/new saves and source-specific ending of panic when Broken.
4. Do not treat this adapter as complete E08/E09 parity. Outstanding work includes other stress responses, repeating/overlapping panic precedence, full dropped-item and supply handling, Paranoid cooperation restrictions, Hesitant initiative order, cover/scream/flee/frenzy/catatonia, panic spread, lawful recovery/Command, clocks and clinical effects across all adventures. Separate issues own helping, action scheduling and medical systems.
